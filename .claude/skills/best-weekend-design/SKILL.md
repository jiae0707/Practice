# 최고의 주말 설계

## 이 스킬이 하는 일

사용자의 테마·상황·제약을 받아 **토요일/일요일(또는 지정한 휴일) 시간표**를 만든다.
혼자 초안을 쓰고 끝내지 않고, 성격이 다른 5명이 **최소 4라운드** 토론해서 서로의
사각지대를 메운 뒤 채점한다. **5명 평균 9.5점 이상**이 나올 때까지 고친다.

좋은 주말 계획이 어려운 이유는 아이디어가 없어서가 아니라, 한 사람의 관점이
꼭 한쪽으로 기울기 때문이다. 일정을 짜는 사람은 욕심을 부려 과밀하게 만들고,
효율만 보는 사람은 재미없는 표를 만들고, 취향만 보는 사람은 동선을 망친다.
그래서 역할을 나눠 서로를 견제시킨다.

---

## 설계 원칙

모든 라운드에서 이 원칙들이 판단 기준이 된다. 채점의 '테마 적합성'과
'실행 가능성'은 결국 이 목록을 얼마나 지켰는가다.

**밀도**
- 하루 최소 **5개의 의미 있는 활동**을 포함한다
- 단순 이동, 식사, 대기시간을 억지로 활동 개수에 포함하지 않는다.
  숫자를 채우려고 "이동 30분"을 활동으로 세는 순간 이 원칙은 죽는다
- 같은 활동이나 **유사한** 활동을 반복하지 않는다. 카페 두 곳은 서로 다른 활동이 아니다
- 지나치게 빡빡한 일정은 피한다. **자유시간 또는 완충시간을 반드시 포함한다**

**동선**
- 이동 동선이 꼬이지 않도록 **지역을 묶어서** 설계한다
- 사용자의 **이동수단과 실제 이동시간**을 고려한다. 도보 10분과 지하철 40분은
  같은 '이동'이 아니다
- **이미 잡힌 약속을 중심으로** 전후 활동을 최적화한다. 약속이 앵커고 나머지가 위성이다

**내용**
- 친구를 만나는 일정이면 약속 장소 **주변의** 전시·공연·카페·식당을 함께 고려한다
- 집에서 보내는 일정이면 집안일·집 개선·요리·운동·취미·휴식을 **균형 있게** 조합한다
- **생산성 테마라도 휴식 없는 일정으로 만들지 않는다.** 주말을 평일로 만들면
  다음 주가 무너진다
- **휴식 테마라도 하루가 무의미하게 흘러가게 두지 않는다.** 아무것도 안 한 하루와
  잘 쉰 하루는 다르다. 쉬는 것에도 형태가 있어야 한다

**정확성**
- 장소 추천이 필요하면 **최신 웹 정보를 검색**하고 영업 여부와 그 날짜의 운영 여부를
  확인한다 (아래 '장소를 추천할 때' 참고)

## 진행 순서

### 0단계 — 사용자 파일 두 개를 먼저 읽는다

1. **`references/user-profile.md`** — 생활 리듬(기상·취침), 고정 습관, 선호와 기피,
   수정 요청 처리 방식. 이걸 안 읽고 짠 일정은 남의 주말이다
2. **`references/recurring-rules.md`** — 주기가 돌아온 반복 활동

고정 규칙 다루는 법:

- `마지막 실행 + 주기 ≤ 이번 주말의 마지막 날`이면 **주기가 돌아온 것**이다.
  도래한 항목은 블랙의 초안에 처음부터 들어가 있어야 한다. 나중에 끼워 넣으면
  좋은 시간대는 이미 다 차 있다
- 주기가 아직 안 온 항목은 넣지 않는다. 매주 다 넣으면 목록이 의미를 잃는다
- `조건부` 규칙은 조건이 맞는지 내가 판단해서 넣고, 이유를 한 줄 남긴다
- 사용자가 새 규칙이나 생활 변화를 말하면 **해당 파일에 바로 반영한다.**
  기억하겠다고 말만 하는 건 소용이 없다 — 다음 세션의 나는 이 대화를 못 본다
- 일정이 확정되면 이번에 실제로 넣은 항목의 **마지막 실행 날짜를 갱신**하고
  사용자에게 한 줄로 알린다

### 1단계 — 입력 받기 (짧게, 한 번에)

**테마는 사용자가 고르게 한다.** `AskUserQuestion`으로 물어보되, 대화에 이미
답이 있으면 다시 묻지 않는다. 프로필에서 이미 아는 것(기상 시간 등)은 절대 다시 묻지 않는다.

1. **테마** — 생산성 / 휴식·회복 / 소셜(사람 만나기) / 집콕 정비
   (`references/themes.md` 참고. "반반"이면 하루씩 나눈다)
2. **이미 잡힌 약속** — 시간과 장소. 있으면 이게 설계의 앵커다
3. **이동수단** — 도보·대중교통·자차. 이동시간 계산의 전제가 달라진다

날짜를 안 주면 다가오는 토·일로 잡고 그렇게 가정했다고 밝힌다.
"알아서 해줘"면 **묻지 말고** 프로필 기반 기본값으로 진행하고 가정을 명시한다.
답을 기다리느라 아무것도 못 내놓는 게 제일 나쁜 결과다.

### 2단계 — 5인 토론 (최소 4라운드, 예외 없음)

`references/personas.md`를 읽고 각자의 목소리를 유지한다. 라운드 구조와 채점
규칙은 `references/debate-protocol.md`에 있다.

| 라운드 | 하는 일 |
|---|---|
| R1 | 블랙이 초안 제시 → 레드/블루/실버/골드가 각자 관점에서 지적 (레드는 삭제 요구 필수) |
| R2 | 블랙이 반영해 2안 → 동선·중복·체력 집중 검증 |
| R3 | 디테일 채우기 (실버의 집안일 순서, 골드의 장소·아이템, 블루의 업그레이드) + 레드의 2차 삭제 |
| R4 | 최종안 확정 + 5인 채점 (10점 만점) |
| R5+ | 미달이면 **최저점자가 개선안을 직접 제시** → 블랙이 그 항목만 수정 → 재채점 |

4라운드는 하한이지 목표가 아니다. 초안이 좋아 보여서 일찍 끝내고 싶어진다면,
그건 대개 아직 아무도 제대로 안 본 것이다.

토론은 **실제로 이견이 오가야** 의미가 있다. 각 라운드에서 최소 한 개는
**바뀐 것**이 있어야 하고, 무엇이 왜 바뀌었는지 남긴다.

**점수는 일정의 실제 품질에만 근거한다.** 라운드를 많이 돌았다는 이유로,
혹은 기준을 넘겨야 한다는 이유로 점수를 올리지 않는다. 최선을 다해도 9.2라면
**9.2라고 보고하고** 무엇이 충돌하는지 설명한 뒤 선택지를 제시한다.

### 3단계 — 하드 제약 검증

- **하루 5개 이상 의미 있는 활동** (식사·이동·5분짜리 습관은 제외)
- **중복 금지** — 같은 활동 반복 금지, 유사 카테고리 하루 2회까지
- **동선 혼란 금지** — 한 방향으로 흐르게. A→B→A 핑퐁 금지, 지역 이동 하루 2회 이하
- **버퍼** — 활동 사이 최소 15분, 지역 이동이 끼면 이동시간 + 15분
- **활동 시간대** — 프로필의 기상~취침 범위를 벗어나지 않는다
- **고정 규칙 이행** — 주기가 돌아온 항목이 빠짐없이
- **평균 9.5점 이상**, 개별 9.0 미만 없음 (일정을 고쳐서 넘기는 것이지 점수를 고쳐서가 아니다)

눈으로 하지 말고 스크립트로 돌린다:

```bash
python3 .claude/skills/best-weekend-design/scripts/validate_schedule.py <schedule.json> \
        --rules .claude/skills/best-weekend-design/references/recurring-rules.md \
        --window 05:00-21:00
```

`--window`는 프로필의 기상~취침 시간이다. JSON 형식은 `references/schedule-schema.md` 참고.
스크립트가 잡는 건 기계적으로 확인 가능한 것들이고, "이 조합이 실제로 즐거운가"는
여전히 토론의 몫이다.

### 4단계 — 출력

`assets/output-template.md` 구조를 따른다: 한 줄 요약 → 요일별 시간표(표) →
준비물 → 토론 로그(바뀐 것 중심) → 점수표.

"캘린더"라고 했으면 표로 충분하다. 시각적인 걸 원하거나 공유할 계획이면
HTML 아티팩트로 만든다 (그때는 `artifact-design` 스킬을 먼저 읽는다).

### 5단계 — 수정 요청 대응

사용자가 "이건 별로야", "갑자기 ~하고 싶어"라고 하면 **그 시점 이후 일정을
다시 계산한다.** 항목 하나만 갈아 끼우고 끝내지 않는다 — 시간이 밀리면 뒤가 밀리고
장소가 바뀌면 동선이 바뀐다. 자세한 처리 방식은 `user-profile.md`의
'일정 수정 요청 처리'에 있다.

## 장소를 추천할 때

골드는 "이 동네에 이런 분위기의 카페가 많다"처럼 유형과 분위기를 제안하는 데 강하다.
하지만 실제 가게의 영업시간, 가격, 휴무일, 존재 여부는 지어내기 쉬운 정보다.
지어낸 가게 이름 하나가 주말 전체를 망친다.

- **웹 검색을 쓸 수 있으면 반드시 검색한다.** 그 가게가 지금도 영업하는지,
  **그 날짜에** 여는지(월요일 휴무, 격주 휴무, 공휴일 단축 운영)를 확인한다.
  미술관·전시는 특히 휴관일이 있고, 전시 자체의 종료일도 확인 대상이다
- 검색으로 확인한 것만 실명으로 쓴다. 확인 못 했으면
  **"OO역 3번 출구 도보 5분 내 로스터리 카페(직접 검색 필요)"** 같은 유형 제안으로 쓰고,
  표 하단에 "장소 실명 미확인 — 방문 전 확인 필요"를 남긴다
- 영업시간·가격은 검색으로 확인했더라도 "변동 가능"임을 전제로 쓴다

## 상황별 무게중심

**친구를 만난다** → 약속 장소가 앵커. 반경 도보 15분 안에서 묶는다.
문화생활(전시·공연·팝업) → 식사 → 카페 순이 자연스럽다. 먼저 뭔가를 함께 보면
대화 소재가 생겨 카페 시간이 잘 풀린다. 전시는 오픈 직후나 마감 2시간 전이 한산하다.

**집에 있는다** → 실버가 주도한다. 집안일은 **위에서 아래로, 마른 것에서 젖은 것으로**
(먼지 → 정리 → 바닥 → 물청소). 순서를 어기면 두 번 일한다. 집안일 블록 사이에
여가를 끼워 하루가 노동으로만 채워지지 않게 한다. 집 개선은 하나만 — 여러 개
벌이면 다 미완성으로 끝난다.

**생산성 테마** → 인지 부하가 높은 일을 이른 아침에. 딥워크 90분 + 휴식 20분 리듬.
오후에는 가벼운 정리·행정. 레드가 "이건 주말 일인가, 평일에 밀린 일인가"를 골라낸다.

**휴식 테마** → 활동 5개를 채우되 **밀도**를 낮춘다. 산책·목욕·독서·낮잠도 정식 활동이다.
분 단위로 쪼갠 표는 그 자체로 실패다. 시간을 폭으로 적는다(예: 14:00~16:00 느슨한 독서).
그렇다고 하루를 통째로 비워두면 "무의미하게 흘러간 하루"가 된다.

## 참고 파일

- `references/user-profile.md` — **매번 가장 먼저.** 생활 리듬, 고정 습관, 선호, 수정 처리
- `references/recurring-rules.md` — 주기 반복 활동. 읽고, 끝나면 실행일 갱신
- `references/personas.md` — 5인의 성격, 말투, 체크리스트
- `references/debate-protocol.md` — 라운드 구조, 채점 5항목, 점수 인플레 방지
- `references/themes.md` — 테마별 정의와 활동 풀
- `references/schedule-schema.md` — 검증 스크립트가 먹는 JSON 형식
- `assets/output-template.md` — 최종 출력 템플릿
- `scripts/validate_schedule.py` — 하드 제약 자동 검증
