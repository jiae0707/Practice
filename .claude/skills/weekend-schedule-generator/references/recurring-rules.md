# 고정 규칙 (사용자의 반복 주말 활동)

사용자가 "주말마다/격주로 꼭 해야 하는 것"으로 정해둔 항목이다.
**모든 일정 생성은 이 파일을 읽는 것에서 시작한다.** 주기가 돌아온 항목은
블랙의 초안에 이미 들어가 있어야 하고, 토론에서 잘려나가서는 안 된다.
(레드도 이 항목만은 삭제 대상으로 지목하지 않는다. 대신 *배치가 나쁘면* 지적한다.)

이 파일은 사용자의 것이다. 사용자가 새 규칙을 말하면 여기에 추가하고,
그만두겠다고 하면 지운다. 일정이 확정되면 이번 주말에 실제로 넣은 항목의
**마지막 실행 날짜를 갱신**한다 — 갱신하지 않으면 다음 주에 주기 계산이 틀어진다.

## 규칙 목록

| 활동 | 주기 | 마지막 실행 | 배치 힌트 |
|---|---|---|---|
| 화분 물주기 | 2주 | 2026-08-02 | 아침, 5~10분. 외출 전에 끝내는 게 안전 |
| 다음 주 입을 옷 정하기 | 매주 | 2026-08-09 | 일요일 저녁, 20~30분. 세탁·건조가 끝난 뒤에 |

## 표 작성 규칙

검증 스크립트가 이 표를 파싱하므로 형식을 지킨다.

- **활동** — 일정표 제목에 그대로 들어갈 짧은 이름. 검증은 이 문자열이 활동 제목에
  포함되는지로 확인한다. "화분 물주기"로 적어두면 "베란다 화분 물주기"도 통과한다.
  반대로 너무 길게(“2주에 한 번 화분에 물 주기”) 적으면 매칭이 깨진다
- **주기** — `매주` `2주` `격주` `3주` `매월` `월 1회` 형태. 숫자+주/개월도 인식한다
- **마지막 실행** — `YYYY-MM-DD`. 모르면 `미기록`으로 두면 항상 '주기 도래'로 취급한다
- **배치 힌트** — 언제·얼마나 걸리는지. 블랙이 초안을 짤 때 이걸 근거로 시간을 잡는다

## 주기가 돌아왔는지 판단

`마지막 실행 + 주기 ≤ 이번 주말의 마지막 날`이면 도래한 것으로 본다.
예: 화분 물주기를 8/2에 했고 주기가 2주면 8/16이 다음 차례이므로,
8/15~8/16 주말에는 **반드시 들어가야 한다**.

스크립트로 확인한다:

```bash
python3 scripts/validate_schedule.py schedule.json \
        --rules references/recurring-rules.md
```

주기가 돌아왔는데 일정에 없으면 `ERROR`로 잡힌다.

## 규칙을 다룰 때 주의할 것

- 주기가 **아직 안 돌아온** 항목은 넣지 않는다. 매주 억지로 다 넣으면 이 목록이
  의미를 잃고, 사용자는 자기가 정한 규칙을 무시하기 시작한다
- 사용자가 "이번엔 건너뛸래"라고 하면 넣지 않되, 마지막 실행 날짜는 **갱신하지 않는다**
  (건너뛴 것이지 한 것이 아니다). 다음 주말에 다시 도래 항목으로 올라온다
- 규칙 항목도 하루 활동 5개에 포함된다. 다만 5분짜리 화분 물주기 5개로
  하루를 채우는 건 규칙의 취지가 아니다 — 레드가 이걸 잡는다
