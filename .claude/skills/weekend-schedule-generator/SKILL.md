# 주말 일정 생성기 (5인 토론형)

## 이 스킬이 하는 일

사용자의 테마·상황·제약을 받아 **토요일/일요일(또는 지정한 휴일) 시간표**를 만든다.
혼자 초안을 쓰고 끝내지 않고, 성격이 다른 5명이 **최소 4라운드** 토론해서 서로의
사각지대를 메운 뒤 채점한다. **5명 평균 9.5점 이상**이 나올 때까지 고친다.

좋은 주말 계획이 어려운 이유는 아이디어가 없어서가 아니라, 한 사람의 관점이
꼭 한쪽으로 기울기 때문이다. 일정을 짜는 사람은 욕심을 부려 과밀하게 만들고,
효율만 보는 사람은 재미없는 표를 만들고, 취향만 보는 사람은 동선을 망친다.
그래서 역할을 나눠 서로를 견제시킨다.

---

## 진행 순서

### 0단계 — 고정 규칙 먼저 읽기

`references/recurring-rules.md`를 **가장 먼저** 읽는다. 사용자가 "주말마다 꼭 해야 한다"고
정해둔 항목들(화분 물주기, 다음 주 입을 옷 정하기 등)이 주기와 함께 들어 있다.

- `마지막 실행 + 주기 ≤ 이번 주말의 마지막 날`이면 **주기가 돌아온 것**이다.
  도래한 항목은 블랙의 초안에 처음부터 들어가 있어야 한다. 나중에 끼워 넣으면
  좋은 시간대는 이미 다 차 있고, 결국 23시에 밀어 넣게 된다
- 주기가 아직 안 온 항목은 넣지 않는다. 매주 다 넣으면 목록이 의미를 잃는다
- 사용자가 대화 중에 새 규칙을 말하면 (“앞으로 주말마다 ~할래”) **이 파일에 추가한다.**
  기억하겠다고 말만 하는 건 소용이 없다 — 다음 세션의 나는 이 대화를 못 본다.
  파일에 적힌 것만 남는다
- 일정이 확정되면 이번에 실제로 넣은 항목의 **마지막 실행 날짜를 갱신**하고,
  변경 사실을 사용자에게 한 줄로 알린다

### 1단계 — 입력 받기 (짧게, 한 번에)

**테마는 사용자가 고르게 한다.** `AskUserQuestion`으로 물어보되, 대화에 이미
답이 있으면 다시 묻지 않는다. 한 번의 질문 묶음에 최대 4개까지 담아 왕복을 줄인다.

물어볼 것:

1. **테마** — 생산성 / 휴식·회복 / 소셜(사람 만나기) / 집콕 정비 중 선택
   (테마별 성격은 `references/themes.md` 참고. 사용자가 "반반"이라고 하면 하루씩 나눈다.)
2. **어디서** — 집 위주인지, 특정 지역(예: 성수, 강남, 대구 동성로)에서 약속이 있는지
3. **누구와 / 제약** — 혼자·친구·가족·연인, 예산 감각, 차량 유무, 기상·귀가 시간

날짜를 안 주면 다가오는 토·일로 잡고, 그렇게 가정했다고 한 줄 밝힌다.
사용자가 "알아서 해줘"라고 하면 **묻지 말고** 가장 무난한 가정(집 근처 + 혼합 테마 +
09:00 기상 + 중간 예산)으로 진행하고, 결과 위에 가정을 명시한다. 답을 기다리느라
아무것도 못 내놓는 게 제일 나쁜 결과다.

### 2단계 — 5인 토론 (최소 4라운드, 예외 없음)

`references/personas.md`를 읽고 각자의 목소리를 유지한다. 라운드 구조와 채점
규칙은 `references/debate-protocol.md`에 있다. 요약하면:

| 라운드 | 하는 일 |
|---|---|
| R1 | 블랙이 초안 제시 → 레드/블루/실버/골드가 각자 관점에서 지적 (레드는 삭제 요구 필수) |
| R2 | 블랙이 반영해 2안 → 동선·중복·체력 집중 검증 |
| R3 | 디테일 채우기 (실버의 집안일 순서, 골드의 장소·아이템, 블루의 업그레이드 아이디어) + 레드의 2차 삭제 |
| R4 | 최종안 확정 + 5인 채점 (10점 만점) |
| R5+ | 미달이면 **최저점자가 개선안을 직접 제시** → 블랙이 그 항목만 수정 → 재채점 |

4라운드는 하한이지 목표가 아니다. 초안이 좋아 보여서 일찍 끝내고 싶어진다면,
그건 대개 아직 아무도 제대로 안 본 것이다.

토론은 **실제로 이견이 오가야** 의미가 있다. 네 명이 "좋습니다"만 반복하면
라운드를 채워도 계획은 나아지지 않는다. 각 라운드에서 최소 한 개는 **바뀐 것**이
있어야 하고, 무엇이 왜 바뀌었는지 남긴다.

**점수는 일정의 실제 품질에만 근거한다.** 라운드를 많이 돌았다는 이유로,
혹은 기준을 넘겨야 한다는 이유로 점수를 올리지 않는다. 일정이 그대로인데 점수만
올랐다면 그건 채점이 아니라 조작이고, 사용자는 9.5라는 숫자가 아니라 9.5짜리
주말을 원한 것이다. 최선을 다해도 9.2라면 **9.2라고 보고하고** 무엇이 충돌하는지
설명한 뒤 선택지를 제시한다 — 토요일 오후에 실패로 드러나는 것보다 훨씬 낫다.

### 3단계 — 하드 제약 검증

최종안은 아래를 반드시 만족한다. 어기면 3단계로 돌아간다.

- **하루 5개 이상 활동** (식사·이동은 활동 수에 포함하지 않는다. 이동은 별도 표기)
- **중복 금지** — 같은 활동을 이틀에 걸쳐 반복하지 않는다. 같은 카테고리도
  하루 2회를 넘기지 않는다. (식사·휴식 카테고리는 예외)
- **동선 혼란 금지** — 하루 이동은 한 방향으로 흐르게 짠다. A지역 → B지역 → A지역처럼
  되돌아오는 구간(핑퐁)은 금지. 지역 이동은 하루 2회 이하가 기본이고,
  각 이동에 예상 소요 시간을 적는다.
- **버퍼** — 활동 사이에 최소 15분 여유. 지역 이동이 끼면 이동시간 + 15분.
- **고정 규칙 이행** — 주기가 돌아온 `recurring-rules.md` 항목이 빠짐없이 들어 있어야 한다.
- **평균 9.5점 이상**, 개별 점수도 9.0 미만이 없어야 한다.
  단 이 기준은 **일정을 고쳐서** 넘기는 것이지 점수를 고쳐서 넘기는 게 아니다.

검증은 눈으로 하지 말고 스크립트로 돌린다:

```bash
python3 .claude/skills/weekend-schedule-generator/scripts/validate_schedule.py <schedule.json> \
        --rules .claude/skills/weekend-schedule-generator/references/recurring-rules.md
```

JSON 형식은 `references/schedule-schema.md`에 있다. 스크립트가 잡아내는 건
기계적으로 확인 가능한 것들(활동 수, 시간 겹침, 핑퐁 동선, 버퍼, 점수)이고,
"이 조합이 실제로 즐거운가"는 여전히 토론의 몫이다.

### 4단계 — 출력

`assets/output-template.md`의 구조를 따른다. 핵심은:

1. **한 줄 요약** — 테마, 지역, 총 활동 수, 예상 비용, 총 이동 시간
2. **요일별 시간표** (표) — 시간 | 활동 | 장소 | 소요 | 이동 | 메모
3. **준비물 / 체크리스트** — 실버·골드가 챙긴 것들
4. **토론 로그 요약** — 라운드별로 무엇이 왜 바뀌었는지 3~5줄씩
5. **최종 점수표** — 5인 × 5항목, 평균

사용자가 "캘린더"라고 했으면 표만으로 충분하다. 시각적인 걸 원하거나 공유할
계획이면 HTML 아티팩트로 만들어 링크를 준다 (그때는 `artifact-design` 스킬을 먼저 읽는다).

## 장소를 추천할 때의 정직성

골드는 "요즘 성수에 이런 감성의 카페가 많다"처럼 **유형과 분위기**를 제안하는 데
강하다. 하지만 실제 가게의 영업시간, 가격, 휴무일, 존재 여부는 모델이 지어내기
쉬운 정보다. 지어낸 가게 이름 하나가 주말 전체를 망친다.

- 웹 검색을 쓸 수 있으면 **실명 추천 전에 검색해 확인**하고, 확인한 것만 실명으로 쓴다.
- 검색이 없으면 실명 대신 **"OO역 3번 출구 도보 5분 내 로스터리 카페(직접 검색 필요)"**
  같은 유형 제안으로 쓰고, 표 하단에 "장소 실명은 미확인 — 예약 전 확인 필요"를 남긴다.
- 영업시간·가격은 "보통 이 정도" 수준의 감각으로만 쓰고 확정 정보처럼 말하지 않는다.

## 상황별 무게중심

**친구를 만난다** → 약속 장소를 앵커로 잡고 반경 도보 15분 안에서 묶는다.
문화생활(전시·공연·팝업) → 식사 → 카페 순이 자연스럽다. 전시는 오픈 직후나
마감 2시간 전이 한산하다. 골드가 장소, 레드가 "이동 20분짜리 카페는 빼라"를 맡는다.

**집에 있는다** → 실버가 주도한다. 집안일은 **위에서 아래로, 마른 것에서 젖은 것으로**
(먼지 → 정리 → 바닥 → 물청소) 순서가 정해져 있어 순서를 어기면 두 번 일한다.
집안일 블록 사이에 여가를 끼워 넣어 하루가 노동으로만 채워지지 않게 한다.
집 개선(수납 교체, 조명, 화분)은 하나만 — 여러 개 벌이면 다 미완성으로 끝난다.

**생산성 테마** → 인지 부하가 높은 일을 오전에 배치한다. 딥워크 90분 + 휴식 20분
리듬이 기본이고, 오후에는 가벼운 정리·행정 업무를 둔다. 레드가 "이건 주말에
할 일이 아니라 평일에 밀린 일"인지 골라낸다.

**휴식 테마** → 활동 5개를 채우되 **밀도**를 낮춘다. 산책·목욕·독서·낮잠도 정식
활동이다. 휴식 테마에서 분 단위로 쪼갠 표는 그 자체로 실패다. 시간을 폭으로
적는다(예: 14:00~16:00 느슨한 독서).

## 참고 파일

- `references/recurring-rules.md` — 사용자의 고정 반복 활동. **매번 가장 먼저 읽고, 끝나면 갱신**
- `references/personas.md` — 5인의 성격, 말투, 각자가 반드시 확인하는 체크리스트
- `references/debate-protocol.md` — 라운드 구조, 채점 5항목, 점수 인플레 방지, 교착 시 처리
- `references/themes.md` — 테마별 정의와 활동 풀
- `references/schedule-schema.md` — 검증 스크립트가 먹는 JSON 형식
- `assets/output-template.md` — 최종 출력 템플릿
- `scripts/validate_schedule.py` — 하드 제약 자동 검증
