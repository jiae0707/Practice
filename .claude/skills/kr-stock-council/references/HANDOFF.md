# 인수인계 — 새 창이 처음 읽는 문서

이 스킬은 **기존 창에서 3주간 쌓아 올린 것**이고, 새 창은 그 기억이 없다.
아래는 다시 만들 수 없는 것들만 적었다. 시세나 계산은 스크립트가 다시 내지만,
**어떻게 틀렸는지의 기록은 여기 없으면 사라진다.**

> 갱신일 2026-08-19 · 이 문서는 새 창이 이어받은 뒤에도 계속 갱신한다

## 1. 사용자에 대해 (투자 부분만)

| | |
|---|---|
| **손절을 싫어한다** | 파는 건 회사가 "망한다"고 판단될 때뿐 |
| **"망한다"의 정의** | 상장폐지가 아니다. **"성장성이 없고 산업에서 도태돼 본전 회복 가능성이 없다"** — 사용자 본인의 말 |
| 손절을 제안하려면 | **손실을 메울 계획을 같이** 낸다. 그것 없이 "파세요"는 안 받아들여진다 |
| 목표 | "최대한 안정적이되 높은 수익률" |
| **장중에 아무것도 못 한다** | 09:00~15:30 근무. 모든 지시는 **아침에 지정가 예약주문으로 걸 수 있는 형태**여야 한다 |
| 자료를 잘 준다 | IR PDF, 재무 캡처, 공시 원문을 요청하면 준다. **다만 요청이 잦으면 지친다** — 2026-08-19에 "너 달라는거 대응하기 힘들다"고 했다 |

### 사용자가 화냈던 지점 (같은 실수 반복 금지)

- **"뭐 지적할때마다 결론이 완전히 바뀌는데 내가 어떻게 널 믿을 수 있겠어?"**
  → 표류(drift) 문제. `decisions.py`와 R3.5 관문이 여기서 나왔다
- **"바보야.. 넌 나보다 모르냐? 검색 안해?"**
  → 넥스틸이 −9.06% 빠졌는데 쿼리 한 번 잘못 쓰고 "원인 미확인"으로 넘겼다
- **"지금 너무 별로야"**
  → 미국 지표를 사용자가 캡처해 주기를 기다렸다. **이제 내가 다 검색한다**
- **"너 진짜 답답하다.. 뭐 이렇게 맨날 틀리냐"**
  → 삼성전자 BPS를 연말 추정치로 쓰고 현재값처럼 계산했다

## 2. 내가 틀린 방식 — 이게 이 문서의 핵심이다

### 근본 원인 하나

> **숫자를 받으면 "무엇의·언제의 값인지" 확인하지 않고 계산에 넣는다.**

5대 오류가 전부 여기서 나왔다.

2026-08-19에 **여섯 번째**가 붙었고, 이건 결이 다르다.
앞의 다섯은 *입력값*을 잘못 봤지만, 이건 **내가 만든 숫자의 의미**를 잘못 봤다.
지정가는 주문 파라미터인데 체결가로 취급했다. 사용자의 말이 정확하다 —
**"네가 말하는 거래 가격은 신뢰성이 낮다."** 가격은 이제 `data/fills.json`으로 잰다.

### 자료 등급제

| 등급 | 무엇 | 성적 |
|---|---|---|
| **1급** | 공시 원문, IR PDF, 사용자 캡처 | **4/4 맞음** |
| 2급 | 언론 기사 원문 | 혼재 |
| **3급** | 검색 요약 | 확인된 것 중 **0/7 맞음** |

3급으로 확인된 오류: KT 배당 6.69%(→4.53%), 하나금융 PBR 0.5(→0.74)·PER 5.1(→8.28),
넥스틸 소송 3,500억(→미확인), 8/17 미국 지수 3개 전부.

**3급만으로 결론을 내지 않는다.** 쓰더라도 "확인 필요"를 붙인다.

### 실제 사례 5개

| 무엇 | 어떻게 틀렸나 | 무엇으로 잡았나 |
|---|---|---|
| 삼성전자 BPS | 연말 추정 109,367을 현재값으로 씀 → 요구 ROE 22.0%로 과소평가 | 2Q말 자본 579.31조 ÷ 66.0억주 = **87,774원**, 요구 ROE **26.7%** |
| 넥스틸 불성실공시 | 제목만 보고 관리종목 위험으로 판정, **정리 권고** | 원문에 **부과벌점 0, 누계벌점 0, 관리종목 미해당**. 위반은 하루 지연공시, 제재금 800만원 → **권고 철회** |

| 8/17 미국 지수 | 검색으로 나스닥·S&P·다우를 채움 → 셋 다 틀림 | 다음날 캡처의 **전일비로 역산**(종가 ÷ (1+등락률)) |
| **지정가 = 체결가로 계산** | 삼성 첫 칸 268,500을 안 사서 "975,000원 아꼈다"고 씀. **갭하락하면 그 주문은 시가에 체결된다** — 268,500을 낼 일이 없었다 | 사용자 지적. `data/fills.json`과 SKILL.md의 "지정가는 예상 체결가가 아니다"가 여기서 나왔다 |

## 3. DART — 지금 가장 중요한 것

```
python3 scripts/dart.py --check      # 키·도메인을 갈라서 점검
python3 scripts/dart.py --setup      # 고유번호 캐시(최초 1회)
python3 scripts/dart.py --list 넥스틸 --since 20251101
python3 scripts/dart.py --fin 화인베스틸 --year 2026 --quarter 2
python3 scripts/dart.py --doc 20251127000123
```

**두 가지가 다 있어야 한다. 하나만으로는 한 글자도 못 읽는다.**

1. `DART_API_KEY` 환경변수 — opendart.fss.or.kr에서 무료 발급
2. **`opendart.fss.or.kr` 도메인이 이 환경의 네트워크 정책에 허용**

2026-08-19 기준 2번이 막혀 있다 (프록시가 CONNECT에 403).
**이건 키 문제가 아니다.** 사용자가 환경 설정에서 도메인을 열어야 한다.
`--check`가 둘을 갈라서 알려주니 원인을 헷갈리지 않는다.

### 창을 옮기면 1번도 다시 없어진다

**`DART_API_KEY`는 저장소가 아니라 창(컨테이너)의 환경변수다.** 새 창을 열면
빈 상태로 시작한다 — 실제로 2026-08-19 인수 시점의 이 창에서 키가 미설정이었다.
그러니 창을 옮긴 뒤 `--check`가 "키 없음"을 내도 **전에 넣었던 키가 지워진 게 아니라
이 창에 아직 안 들어온 것**이다. 사용자에게 알릴 때 이 구분을 같이 말한다.

키는 저장소에 커밋하지 않는다(공개 저장소다). 환경 설정의 환경변수로 넣는다.

### 키 발급 절차 (2026-08-19 확인 · 검색 기준이라 3급)

opendart.fss.or.kr이 이 환경에서 막혀 있어 **원문으로 확인하지 못했다.** 화면이 다르면 실제 화면을 따른다.

1. opendart.fss.or.kr 회원가입 (이메일 인증)
2. 상단 **인증키 신청/관리** → 약관 동의 → 사용자구분(개인)·이메일·비밀번호·API 사용용도 입력 → 등록
3. 개인회원은 즉시 발급. **마이페이지 → 오픈API 이용현황**에서 40자 키를 복사
   - 신청 화면: `https://opendart.fss.or.kr/uss/umt/EgovMberInsertView.do`
   - 일일 호출 한도 20,000건 (3급. 약관상 한도는 금감원이 변경할 수 있다)

### 환경에 넣는 법 (공식 문서 원문 = 1급)

claude.ai/code 메시지 입력창 위의 **클라우드 아이콘**(현재 환경 이름) → 환경에 커서를 올려
**설정(톱니) 아이콘** → 다이얼로그에서 두 가지를 같이 고친다. 별도 설정 페이지나 URL은 없다.

| 칸 | 넣을 것 |
|---|---|
| **Environment variables** | `DART_API_KEY=발급받은키` (`.env` 형식, 한 줄에 하나) |
| **Network access** | `Trusted` → **`Custom`**으로 바꾸고 **Allowed domains**에 `opendart.fss.or.kr` |

**Custom으로 바꿀 때 두 가지를 빠뜨리면 다른 게 망가진다:**

- **`Also include default list of common package managers`를 체크한다.** 안 하면 적은 것만 열리고
  GitHub 공개 데이터셋(`raw.githubusercontent.com` — VIX·WTI·환율 자동 수집 경로)이 닫힌다
- **`*.frame.claudeusercontent.com`을 같이 적는다.** 아침 브리핑 아티팩트를 **같은 URL로 갱신**하려면
  기존 아티팩트를 읽어야 하는데, 이 호스트가 없으면 못 읽는다

**설정은 그 뒤에 시작하는 세션부터 적용된다.** 실행 중인 창은 시작할 때 복사한 값을 그대로 쓰므로,
고친 뒤 **새 창을 열어야** 키와 도메인이 들어온다. 새 창의 브랜치 이름을
`OPEN-IN-NEW-WINDOW.md` 표 3️⃣에 다시 적는다.

> ⚠️ 클라우드 환경에는 **비밀값 저장소가 없다.** 환경변수는 그 환경을 쓰는 사람이면 다 읽는다.
> DART 키는 무료·읽기 전용·공개 공시 조회용이고 이 환경은 개인용이라 감수할 만하지만,
> 조직 공유 환경에는 넣지 않는다.

열리는 즉시 위 5개 미확인 항목을 순서대로 처리한다.

## 4. 지금 걸려 있는 주문 (2026-08-19 기준)

전부 **지정가 · 예약 가능**. 사용자는 장중에 못 움직인다.

> 2026-08-19 기준 실제로 걸려 있는 건 **8칸**(현대차 매도 4 + KT 매수 4)이다. 삼성전자는 50주 체결 후 나머지를 걸지 않기로 했다.

> **지정가는 최악의 체결가다.** 갭이 나면 시가에 체결되므로 매도는 더 비싸게, 매수는 더 싸게 잡힌다. 아래 금액을 예상 체결가로 쓰지 않는다.

| | 가격 | 수량/배분 | 상태 |
|---|---|---|---|
| ~~삼성전자 매수~~ | ~~268,500 / 250,000~~ / 230,000 / 205,000 | — | **8/19 종료.** 249,000에 50주 체결(사용자 직접), 남은 칸은 **주문 안 검**. 230,000 접근 시 재판단 |
| **현대차 매도** | 435,000 / 489,240 / 525,480 / 561,720 | 126 / 253 / 379 / 508주 | 전부 미체결 |
| **KT 매수** | 53,400 / 51,900 / 50,800 / 49,000 | 10/15/30/45% · 예산 6,000만 | 전부 미체결 |

### 사다리 규칙 (어기면 사다리가 아니게 된다)

- **첫 칸만 현재가를 따라가고 2~4칸은 고정.** 2~4칸은 목표가라 주가가 흔들려도 안 바꾼다
- **현재가 추종은 매도 사다리에서만.** 매수 첫 칸을 올려 따라가면 추격매수다
- **갭하락을 쫓아 매도 첫 칸을 내리지 않는다.** 그건 손절이다
- 밴드 자체가 바뀔 때만(실적·서사 검증) 사다리 전체를 다시 만든다.
  **주가가 빠졌다는 이유로는 안 바꾼다**

| `decisions.py` (표류/갱신 판정) | 지적할 때마다 결론이 바뀌어 신뢰를 잃었다. **새 사실 없이 바뀌면 표류**다. 현재 표류율 **44%** |

| **실버 = 결론 이력의 관리자** | 비중 30% 이상 종목은 뒤집으려면 **새 사실 + 두 방법의 일치**가 다 필요하다 |
| **R3.5 관문** | 번복 심사 + 레드 교차 검증을 통과해야 출고 |
| 신뢰등급 상/중/하 | **종목의 좋고 나쁨이 아니라 내 판단이 얼마나 두꺼운지**다. '하'는 "믿지 말고 아무것도 하지 마세요" |
| `ladder.py` | "현대차 최고점에 왜 팔지 못했을지 후회돼" → 오르는 중에는 판단할 수 없다. **미리 걸어두면 체결이 된다** |
| `target.py --roe-adjust` 거부 조건 | 적자 연도를 조용히 버려서 "관측치 2년뿐"이라던 게 실은 코드 버그였다 |
| `implied.py --cycle` | 정점이익 종목은 PER이 가장 낮을 때가 가장 위험하다 |
| `trend.py` | 가격만 읽고 거래량을 안 봤다. 현대차 OBV **t=−4.75** — 오르는 동안 물량이 넘어갔다 |

## 7. 산출물 형식

- **결과물은 큰 블록 + 체크리스트 두 층.** 사용자는 잘게 쪼개서 체크한다
- **HTML 아티팩트는 방향성을 앞에, 근거를 뒤에.**
  사용자 요구: *"종목별로 방향성을 앞에 두고, 여러가지 의견(질문 등)은 뒤로 가거나
  굳이 내가 알 필요가 없는 정보는 안보여주는게 좋아"*
  → 순서: 오늘 할 일 → 걸 주문 → 밤사이 → 예상 개장 → 뉴스 반영 → 종목 카드
  → 소형주 → 반증 조건 → 포트폴리오 → `── 이하 근거 ──` → 상세
- 선택지가 갈리는 자리는 **후보 2~3개**를 성격과 함께
- **확인한 것만 사실로 쓴다.** 못 구했으면 "못 구했다"고 쓴다 — 그게 지어내는 것보다 낫다.
  **"검색을 안 한 것"과 "검색했는데 없는 것"은 다르다.** 브리핑에 그 구분을 남긴다
