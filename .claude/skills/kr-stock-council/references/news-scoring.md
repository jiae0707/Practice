# 뉴스를 숫자로 바꾸는 법

텍스트는 회귀에 못 넣지만, **텍스트에서 뽑은 숫자**는 넣을 수 있다.
이 문서는 그 숫자를 만드는 규칙이다. 규칙 없이 매번 감으로 매기면
시계열이 아니라 그날그날의 기분이 된다.

---

## 🚨 첫 번째 규칙 — 주가를 보지 않고 채점한다

이게 이 문서에서 가장 중요하다.

주가가 −12% 빠진 날의 뉴스를 읽으면 그 뉴스가 악재로 보인다. 그렇게 매긴 점수로
회귀를 돌리면 **"악재인 날 주가가 빠졌다"**는 동어반복이 나오고 R²가 가짜로 올라간다.
이걸 **사후 편향(look-ahead bias)**이라 하고, 금융 데이터 분석에서 가장 흔한 실패다.

**절차를 강제한다:**

1. 그날 뉴스만 읽는다. **종가·등락률을 보지 않는다**
2. 아래 기준으로 점수를 매기고 `data/news.json`에 **먼저 저장한다**
3. 저장한 뒤에 주가를 붙인다

이미 주가를 본 날짜는 **`"blind": false`로 표시**한다. 그 날짜는 검증용으로 쓰지 않는다.
표시 없이 섞으면 전체 회귀가 오염된다.

## 두 번째 규칙 — 변수를 3개 이상 만들지 않는다

관측치 104일에 변수 10개를 넣으면 과적합이다. 임베딩·토픽모델은
수천~수만 관측치가 있어야 하고, 여기서는 **감성 강도 하나**가 적정하다.

변수를 늘리고 싶으면 관측치를 먼저 늘린다. 매일 브리핑에서 하루씩 쌓인다.

---

## 채점 기준

날짜별로, **종목별로** 매긴다. 같은 날 뉴스가 현대차엔 호재고 삼성전자엔 무관할 수 있다.

### sentiment — 방향과 세기 (−2 ~ +2)

| 점수 | 기준 |
|---|---|
| **+2** | 실적 컨센서스 상회, 대형 수주 확정, 규제 해제, 배당·자사주 확대 발표 |
| **+1** | 우호적 업황 전망, 경쟁사 부진, 증권사 목표가 상향 |
| **0** | 중립. **판단 안 서면 0을 준다.** 억지로 방향을 잡지 않는다 |
| **−1** | 업황 둔화 전망, 목표가 하향, 경쟁 심화 |
| **−2** | 실적 컨센서스 하회, 관세·규제 신설, 리콜, 소송, 경영 리스크 |

### surprise — 이미 알려진 일인가 (0 ~ 2)

| 점수 | 기준 |
|---|---|
| **0** | 예고된 일정대로 나온 내용. 이미 가격에 있다 |
| **1** | 방향은 예상됐지만 폭이 달랐다 |
| **2** | 아무도 예상 못 한 사건 (돌발 관세, 사고, 갑작스러운 발표) |

### scope — 영향 범위

`firm`(그 회사만) · `sector`(업종 전체) · `macro`(시장 전체)

`macro`는 이미 VIX·환율 팩터가 잡고 있으므로 **뉴스 점수에서는 빼거나 별도로 둔다.**
안 그러면 같은 정보를 두 번 세게 된다(다중공선성).

### 회귀에 넣는 값

```
news_score = sentiment × surprise
```

범위는 −4 ~ +4. **surprise가 0이면 점수도 0**이다 — 예상된 뉴스는 가격에 이미
반영돼 있으므로 그날 수익률을 설명하지 못한다는 뜻이고, 이건 시장 효율성의
기본 가정이다.

## 저장 형식 — `data/news.json`

```json
{
  "2026-06-23": {
    "현대차": {
      "sentiment": -2, "surprise": 2, "scope": "firm",
      "category": "실적·관세",
      "headline": "2분기 영업이익 2.9조, 컨센서스 3.2조 하회 / 미국 한국산 12.5% 관세",
      "blind": false,
      "source": "검색 2026-08-16"
    }
  }
}
```

- `category` — 실적 / 관세 / 규제 / 수주 / 테마 / 지정학 / 경영 / 배당
- `blind` — 주가를 안 보고 매겼으면 `true`. **이게 없으면 검증에 못 쓴다**
- `headline` — 나중에 다시 볼 때 채점 근거를 확인할 수 있어야 한다

## 채점 안 한 날은 0이 아니다

뉴스가 없었던 날과 **내가 확인 안 한 날**은 다르다. 확인 안 한 날은
`null`로 두고 회귀에서 제외한다. 0으로 채우면 "뉴스가 없었다"는
없는 정보를 만들어내는 것이다.

---

## 이 방법의 한계 — 반드시 같이 말한다

1. **채점자가 하나다.** 두 사람이 매기면 일치도를 측정할 수 있지만 여기선 못 한다.
   그래서 점수는 절대값이 아니라 **상대적 순서**로만 읽는다
2. **뉴스 수집이 완전하지 않다.** 검색으로 못 찾은 사건은 0점이 아니라 누락이다
3. **±3σ 사건은 대개 사후에 찾는다.** 그래서 그 날짜들은 구조적으로 `blind: false`다.
   앞으로 매일 쌓는 데이터라야 `blind: true`가 된다
4. **n이 작다.** 60일 미만이면 계수를 보지 않는다

## 그래서 실제 운영은

**매일 아침 브리핑에서 그날 뉴스를 채점하고 저장한다.** 주가는 그날 저녁에
붙는다. 이 순서면 자연스럽게 `blind: true`가 되고, 60거래일쯤 지나면
**진짜 예측력을 가진 회귀**가 된다.

과거 104일을 소급해서 채점하는 건 하지 않는다. 편향이 확실히 들어가고,
그 편향으로 만든 R²는 사용자를 속이는 숫자가 된다.
